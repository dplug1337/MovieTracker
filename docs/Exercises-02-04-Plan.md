# План за упражнения 02–04

> Този материал описва началния етап на проекта. Виж [реализацията за Exercises 02–06](Exercises-02-06.md) за текущия backend и PostgreSQL.

## Проверена отправна точка

- Локалната история включва Exercise 01, кинематографичното заглавие и страницата Movie Insights. Учебните Markdown файлове се виждат като непроследени.
- `origin` сочи към `dplug1337/MovieTracker` за fetch и push.
- Release build за `net8.0` завършва с 0 предупреждения и 0 грешки. Текущият NUnit опит прекъсва преди изпълнение при създаване на `TestResults`.
- Docker CLI е инсталиран, но Docker Engine е недостъпен. При проверката не се откриха `psql` или локална PostgreSQL услуга.

## Източници и отворени въпроси

Публичната начална страница показва `exercises/` и `README.md`. От тази среда съдържанието им и наличието на `codex/` не можаха да бъдат потвърдени. Следващите точки описват работни решения по заявените цели. Конкретните routes, полета, правила и права се сверяват с официалните задания, когато са достъпни. [Официално хранилище](https://github.com/teomihov/MovieTracker)

## Последователност

| Фаза | Планирана реализация | Проверка |
| --- | --- | --- |
| 01 — приключване | Преглед на учебните файлове, отделен документационен commit и проверка на `origin/main`. | Изпълнение на базовите 15 тестови случая в среда с достъпен `TestResults`. |
| 02 — операции с филми | Разширяване на каталог по съществуващия Vertical Slice модел. Отделни slices за операции, с FluentValidation, Result Pattern, ръчен mapping и REST отговори. Свързване на Blazor екрана за детайли и изисканите операции. | Unit проверки на правила и handler-и, HTTP integration проверки на успешни операции, невалидни входове и липсващ филм. Съществуващият GET списък запазва договора си. |
| 03 — PostgreSQL | EF Core и Npgsql в Infrastructure, интерфейси в Application, migration и детерминирани начални филми. Connection string от сървърна конфигурация. При работещ Docker и липса на друго изискване PostgreSQL слуша само локално чрез Compose. | Прилагане на миграция, проверка на schema, запис през API и повторно четене след рестарт. Тестовете за записи използват отделна тестова база. |
| 04 — идентичност и Watchlist | Постоянни акаунти, утвърден password hasher и валидиран краткоживеещ JWT. Като резервно решение клиентът пази access token само в паметта и след презареждане изисква нов вход. Сървърът извежда UserId от валидирания principal. Уникалността на имейла и двойката потребител–филм се налага в базата. | Регистрация, дубликат, вход, невалиден и изтекъл token, анонимни заявки, публичен каталог и изолация между два различни акаунта. |

След всяка фаза прегледът включва build, тестове, приложими HTTP проверки, проверка на Git diff и учебна документация. След верификация следват отделен логически commit и push към проверения `origin/main`. Ratings, Reviews, Statistics и Top Rated остават за Exercise 05.
